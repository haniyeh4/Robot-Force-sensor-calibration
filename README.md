# Data-Driven Self-Calibration of Force Sensing for Industrial Robots with Unknown Tool Attachments

Code and data to reproduce the results of the paper by H. Altafi, S. Sadeghian and K. Zareinia
(Toronto Metropolitan University). Setup: KUKA KR 600 robot, ATI Gamma IP60 SI-130-10 six-axis
force/torque sensor, custom tool holder with surgical forceps.

The framework has two stages:

1. **Quasi-static**: a third-degree polynomial maps end-effector orientation (roll, pitch, yaw) to the
   gravity-induced wrench offset.
2. **Dynamic**: after subtracting the quasi-static prediction, the remaining motion-induced offset is
   predicted from orientation and commanded Cartesian acceleration, using either a second-degree
   polynomial or an MLP.

## Quick start

```bash
python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
./run_all.sh            # about 15-25 min on a laptop CPU
```

Each script can also be run on its own. Outputs:

- `results/*.json`: all metrics
- `results/SUMMARY.md`: manuscript values next to the values this code produces
- `results/models/`: fitted models (quasi-static and dynamic polynomial as joblib, MLP weights and input scaler)
- `figures/`: all result figures

## Method details

These details match the implementation and the reported numbers:

- **Quasi-static data.** 362 poses from a joint-space path (`data/1_TheRightWay.csv`). The robot holds each
  pose for about 1 s before a single 250 Hz frame is logged. The data are split randomly at sample level
  80/20 (`train_test_split`, `random_state=42`): 289 train and 73 test. The benchmark is 56 stationary
  frames recorded separately at manually jogged poses.
- **Dynamic data.** Training pool: two continuous random-motion recordings, L1 and L2 (88,223 samples at
  250 Hz). These are split randomly at sample level 80/20 (`random_state=42`). Benchmark: a separate
  recording, L4 (34,363 samples). A random sample-level split puts temporally adjacent samples in both
  training and test, so the *test* scores are optimistic. The *benchmark* (L4) shares no samples with
  training. `recording_level` in the results gives scores where whole recordings are held out.
- **Dynamic inputs (9).** Roll, pitch, yaw, and the 6-DOF *commanded* Cartesian acceleration (3 linear and
  3 angular, `X_DoubleDot_Cmds`) streamed by the Simulink driver. Inputs are standardized (`StandardScaler`).
- **Targets.** The sensor wrench after the Simulink 5 Hz low-pass filter (`FF_EE`). Dynamic target:
  `FF_EE - FF_EE_Quasi`. Errors against the unfiltered signal are reported separately (`*_vs_raw`).
- **Metrics.** As in the manuscript, `all6_*` metrics average all six wrench components (forces in N,
  torques in N·m). Force-only (`force_*`), per-axis and torque metrics are also reported. %FSO uses
  500 N, as in the manuscript.
- **MLP.** Architecture 9-64-128-64-6 with Linear-ReLU-BatchNorm-Dropout(0.2), giving 18,118 parameters.
  Training: Adam with lr 1e-3, MSE loss, batch 64, 30 epochs. The original training run was not seeded
  and its weights could not be matched to the reported metrics, so the model is retrained here with fixed
  seeds (0–4) and reported as mean ± std. The input scaler is fitted on the training split only.
